# UI Review — GitHub Stars Dashboard（2026-10-09）

> 范围：`index.html` / `css/style.css` / `js/app.js` / `js/logic.js`，数据 `data/stars.json`（147 个仓库）。
> 方法：读代码 + 1440×900（亮/暗）与 390×844 全页截图 + WCAG 对比度计算。
> 结论先行：Neumorphism 外观完成度不错，但**信息架构和可读性是主要问题**——筛选状态不可见、卡片信息与排序不对应、大量 9–11px 低对比文字、装饰元素挤占信息。

## 1. 数据画像（设计应服务于它）

| 维度 | 实际情况 | 设计含义 |
|---|---|---|
| 规模 | 147 个仓库 | 无需 13 页分页；一屏可承载全量列表或"加载更多" |
| 语言 | TS 52 · Py 29 · 无语言 14 · JS 13 · Go 11 · Shell 8 · Rust 7，其余 8 种各 1–3 个 | 长尾应折叠；"无语言"14 个目前无法筛选 |
| 主题 | 632 个不同 topic；claude-code 27 · codex 23 · ai-agents 22 · mcp 19 … | topic 才是这批收藏真正的分类维度，比语言更有信息量 |
| 时间 | 点星集中在 2026-02 ~ 2026-10，6–7 月峰值 | "我最近在关注什么"是天然故事线，目前完全没展示 |
| 简介 | 111 条为机翻中文，部分失真（如 hermes-agent →"与您共同成长的代理商"） | 需要能看原文 |

## 2. 问题清单（按严重度）

### P0 — 功能/信息错误

1. **Topic 筛选状态不可见、无法统一清除。** 点击卡片 topic 后，唯一提示是卡片内该 tag 变红；若该 topic 不在某卡片前 3 个之内就看不到；也没有"清除"入口，只能回去找那个 tag 再点一次（`js/app.js:269-277`）。
2. **"已同步 HH:MM" 是假信息。** 显示的是浏览器加载时间 `new Date()`，不是数据更新时间（`js/app.js:30-31`）；配合常亮的"系统运行中"绿灯，给出错误的系统状态暗示。
3. **卡片日期与排序维度不对应。** 无论按点星/发布/更新排序，卡片永远显示 `pushed_at` 相对时间；`starredDate` 已计算但从未使用（`js/app.js:144-145`）。按"点星时间"排序时用户看不到点星时间。
4. **"ALL" 按钮无激活态**，语言筛选时也不显示 `aria-pressed`；14 个无语言仓库无法被筛选。

### P1 — 可读性与无障碍

5. **字号过小。** topic 标签 0.55rem ≈ 8.8px，卡片日期 0.6rem ≈ 9.6px，语言 chip 0.65rem ≈ 10.4px，且多为全大写等宽字体，中文用户阅读成本高。
6. **对比度不达标（WCAG AA 正文需 ≥ 4.5:1）：**

   | 元素 | 对比度 |
   |---|---|
   | 星数 `#ff4757` on `#e0e5ec`（亮） | **2.64** |
   | 已同步时间 on 统计面板（亮） | **2.42** |
   | 激活排序按钮 白字 on `#ff4757` | 3.34 |
   | topic 标签文字 on recessed（亮） | 3.69 |
   | muted 文字（暗） | 3.42 |
   | muted 文字（亮） | 4.14 |

   Neumorphism 本身依赖同色系阴影区分层级，按钮/输入框边界在暗色模式下几乎消失（见暗色截图搜索框）。
7. **焦点态缺失。** 搜索框 `outline: none`，按钮无 `:focus-visible` 样式，键盘用户无法定位。
8. **Fork 图标 `⑂` 在 JetBrains Mono 中缺字**，渲染成近似 "Ø" 的豆腐块。
9. **无 `prefers-reduced-motion`**，LED 无限脉冲动画。
10. **主题切换图标表达当前状态而非动作**（亮色显示太阳），语义含糊。

### P2 — 信息架构与布局

11. **控制区过重。** 移动端在第一张卡片之前要滚动约 600px：顶栏折行 + 统计面板 + 搜索 + 排序 + 5 行语言 chip。
12. **语言 chip 一视同仁。** 16 个 chip 视觉权重相同，"Markdown 1""CSS 1"与"TypeScript 52"并列，占两行。
13. **统计面板信息量低。** 大面积只承载"147 + 前 5 语言"，且语言统计跟随筛选结果变化而总数不变，含义混乱；暗色模式下"深色显示屏"与背景融为一体，失去层次。
14. **装饰噪音。** 卡片四角螺丝 + 右上通风槽 + 噪点 + 扫描线，挤占名称区（需额外 `padding-right: 20px`），对"找仓库"这一核心任务无贡献。
15. **13 页分页** 对 147 条数据过度切分，跨页搜索/比较不便；分页省略号渲染为禁用按钮。
16. **搜索不匹配 topic**；无 `/` 快捷键、无清空按钮、输入框无 label。
17. **筛选状态不进 URL**，无法分享"我收藏的 MCP 项目"这类视图。

### P3 — 一致性与工程

18. **中英混排不一致**："No matching repos""DATA LOAD FAILED""RETRY""1MO AGO""ALL""repos""GitHub →"与中文界面混用。
19. **Google Fonts 依赖**：在中国大陆加载慢或失败；且 Inter / JetBrains Mono 不含中文字形，中文本来就回落到系统字体。
20. **机翻简介无法查看原文**。
21. 语言色表在 CSS 中重复 3 次（`.lang-dot` / `.lang-toggle` / `.meta-lang`），JS 中再维护一份 `langColors`；Swift/C/CSS/Markdown 等落入灰色。
22. 错误信息 `e.message` 未转义直接拼进 `innerHTML`（`js/app.js:33`），风险低但应顺手修。
23. **数据侧（非 UI）**：原文含任意中文字符的简介不会被翻译，`description_zh` 直接等于中英混合原文（如 `zhuyansen/awesome-claude-video-skills`、`lemomo-ai/lemo-opuscar`），卡片上看起来像"漏翻"。属于 `scripts/translate_descriptions.py` 的判定规则，不在本次 UI 重构范围。

## 3. 保留的优点

- 零依赖、零构建的纯静态架构，`js/logic.js` 已把排序/筛选抽成可测试纯函数——重构可完全复用。
- 暗色模式 token 化、跟随系统 + 手动持久化的逻辑正确。
- 排序升降序切换、topic AND 筛选的交互模型本身合理，只是呈现不足。

## 4. 重构原则（三个方案共同遵守）

1. 内容优先：仓库名、中文简介、星数是第一层级；装饰让位于信息。
2. 全部文字 ≥ 12px，正文对比度 ≥ 4.5:1（亮/暗都满足），可见焦点环。
3. 所有筛选状态可见、可单独移除、可一键清除。
4. 日期显示跟随排序维度。
5. 界面语言统一为简体中文；去掉 Google Fonts，改用系统字体栈。
6. 继续复用 `js/logic.js`，保持零构建。

重构方案原型（A–F）保留在本地 `loft/ui-redesign` 分支的 `design/` 目录；最终选定 A 方案，并在其基础上增加功能分类索引（见 `docs/superpowers/specs/2026-10-09-category-index-design.md`）。
